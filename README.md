# 高校财务管理系统静态原型

根据《第七章 页面设计》实现 30 个可浏览页面：5 个公共页面与 25 个业务页面，页面编号沿用 U0—U4。

## 打开方式

直接双击 `dist/index.html`，使用 Edge 或 Chrome 浏览。全部页面与资源均在本地，无需安装依赖、联网或登录。

也可在本目录执行 `python -m http.server 5173 --directory dist`，打开 `http://localhost:5173`。

## 演示顺序

1. 右上角选择“制单岗 C”，进入报销单受理，保存或提交预置草稿。可修改金额测试明细合计、可用余额与入库单校验。
2. 在状态跟踪点击“进入当前处理页面”，切换“审核岗 A”，签批，再进入财务审核并提交结论。
3. 切回“制单岗 C”，进入制单与付款，生成付款单。
4. 切换“发放岗 P”，提交银行。进入发放回写，导入演示回单并核销。
5. 打开账号台账查看已用额度变化，打开状态跟踪查看同一单据的全过程。
6. 使用“审核岗 A”进入到账对账并自动匹配，查看已核销、多缴挂账、部分核销和未到账四类结果。
7. 打开报表编制，切换模板、导出 CSV 或通过浏览器打印另存 PDF。

## 边界

本项目为静态交互原型，使用虚构人员、账号及业务数据；数据保存在当前浏览器 localStorage。统一身份、真实权限验证、数据库、工资计算、银行支付、资产库、学籍库与事务均未接入；页面中的导入、审批与付款为本地演示。

工资批次使用预置核算结果，不用于实际工资或税费计算。银行账号和单据编号均为演示值。A/P 岗位隔离仅用于演示，不构成生产安全机制。

浏览器打印窗口可另存 PDF；CSV 由浏览器直接下载。清除本网站本地存储后可恢复初始演示数据。

## 检查

执行 `node --check dist/app.js` 检查语法，执行 `node check.cjs` 验证 30 页渲染、审批到核销流程、额度扣减、防重复付款及四类对账结果。该检查不替代真实浏览器视觉验证。
